③ 議價能力：會被繞過還是被強化

【假】若 Agent 成為主要消費端口，各層的命運取決於付款仍走哪一條軌道，而不是「有參與協議」本身。

  • 卡組織：有被繞過的風險，也在把自己寫進新軌。【事】AP2 與 x402 明白支援穩定幣與（AP2）即時轉帳，不一定要走卡〔13〕〔23〕。【事】Mastercard AP4M 自己也支援卡、帳戶與穩定幣，並建構於 x402〔6〕〔7〕；Visa 亦稱 TAP 與 x402 對齊並加入 x402 Foundation〔2〕〔23〕。【估】只要消費端仍用卡或網絡代幣，卡組織的接受網路、授權與爭議規則會被強化，而不是被旁路。【假】若機器對機器微交易大量改走穩定幣或 A2A，傳統交換費可能被壓縮；網絡若成為多軌清算與身分層，則仍可能留下驗證與清算租金。
  • 處理器：協議碎片化反而提高其中介價值。【事】Adyen 以「通用轉譯器」定位、PayPal Agent Ready 一次接 ACP 與 UCP，正是因為商家不想為每個 Agent 重做系統〔18〕〔19〕。【假】若最終收斂成一兩個開放協議且商家直連 Agent，處理器的增量租金會變薄，但仍可能留下代幣化、風控與收單。
  • 錢包：在「對話內結帳」時被強化，在「回商家網站結帳」時回到原位。【事】Google UCP 有限上線走 Google Pay〔16〕〔17〕。【事】OpenAI 則把結帳送回商家自有通道〔11〕。兩者同時存在，顯示入口不一定能鎖住付款。
  • BNPL：必須出現在 Agent 結帳，否則容易被預存卡取代。【事】Klarna／Affirm 的合作就是為了避免 Agent 只剩儲存卡〔20〕〔21〕。【假】若 Agent 為求一次完成而預設發卡行卡，BNPL 的商戶費會流失。
  • 商家責任與爭議。【事】AP2 把 Checkout／Payment Mandate 設計成爭議時的證據〔13〕；Mastercard Framework 提供購買意圖與稽核軌跡，稱或有助避免或解決爭議〔4〕；Amex 預告對「註冊 Agent 錯誤」提供持卡人保護，條款未定〔22〕。【假】若方案規則仍把無人值守 Agent 交易視為高風險 CNP、責任留在商家，商家可能直接封鎖 Agent 流量，協議再完整也無法放量。【假】若發卡行或網絡明確承擔 Agent 執行錯誤，商家接受度會上升，網絡／發卡的風控成本也會上升。

④ 反方情境、推翻條件與資料缺口

  1. 入口只做探索、付款不離開商家。【事】OpenAI 商家頁已把這條路寫成現行優先策略，且對回到商家結帳的購買宣稱不收費〔11〕。【假】若這成為主流，Agent 付款協議的交易費故事會明顯縮小，受益者更像商家既有收單與錢包，而不是新抽成層。推翻條件：主要入口重新推出大規模、向商家收費的對話內結帳，並公布成交量。
  2. 消費者不願預授權無人值守付款。【事】Klarna 上線稿仍要求每筆確認〔21〕；AP2 的 Human Not Present 在 v0.2 仍是「將允許」〔14〕。【假】若詐欺或「Agent 買錯」個案上升，發卡行與監理收緊授權，自主代付就停在演示階段。
  3. 穩定幣／A2A 繞過卡網，或卡網成功收編。【假】若 x402／AP4M 的機器付款放量且清算不走卡，交換費被旁路。相反，若大多數 x402 交易仍由卡組織或穩定幣發行人搭配網絡清算，則「繞過」不成立。推翻或證實都需要公開的軌別成交量，目前未取得。
  4. 協議碎片化拖慢商家採用。【事】同時存在 ACP、UCP、AP2、TAP、Agent Pay、x402 與各家套件〔見表〕。【假】若商家因整合成本而只接一兩個入口，宣稱的「開放互通」就不能轉成規模。
  5. 責任規則與監理。【假】若歐盟 SCA、美國消費者保護或方案規則要求每次 Agent 付款都回到強認證，自動化會放慢。本輪未取得 Agent 交易的正式方案責任轉移文件。
